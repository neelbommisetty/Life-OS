# Life-OS tools API

The package default export and `@life-os/tools/client` expose the HTTP client; `@life-os/tools/server` is the explicit backend-only entry point.

All existing tools operations are available through one authenticated HTTP API. `life` is an HTTP client; it never opens the database, reads provider credentials, or calls provider APIs. Business logic remains in `Tools` on the server.

## Run locally

From the repository root, with PostgreSQL running and the existing root `.env` configured:

```sh
bun run api
```

The server listens on `http://127.0.0.1:4319`. On first start it creates `.local/api/token` with file mode `0600`; the default local CLI reads that token automatically. The token and other runtime files are ignored by Git. The server does not migrate the database automatically.

In another terminal:

```sh
bun run life migrate
bun run life doctor --json
bun run life task list --json
```

Existing task/calendar/library commands, actor rules, questions, JSON output and exit codes are retained. Replace `--db` with `--api-url`; database configuration belongs to the server. `life --help` and `life --version` work without a running API.

| Setting | Used by | Purpose |
| --- | --- | --- |
| `LIFE_API_URL` / `--api-url` | CLI | API base URL; default `http://127.0.0.1:4319` |
| `LIFE_API_TOKEN` | Both | Bearer token; at least 32 characters on the server |
| `LIFE_API_HOST` | Server | Bind address; default `127.0.0.1` |
| `LIFE_API_PORT` | Server | Port; default `4319` |
| `LIFE_API_ORIGINS` | Server | Comma-separated allowed browser origins; none by default |
| `LIFE_DATABASE_URL` | Server | Existing PostgreSQL connection |
| `LIFE_GOOGLE_CLIENT_ID`, `LIFE_GOOGLE_CLIENT_SECRET` | Server | Existing Google OAuth configuration |
| `LIFE_GOOGLE_REDIRECT_URI` | Server | Optional fixed API-hosted callback; see below |
| `LIFE_TMDB_KEY`, `LIFE_IGDB_CLIENT_ID`, `LIFE_IGDB_CLIENT_SECRET` | Server | Existing catalog credentials |
| `LIFE_REGION`, calendar refresh settings | Server | Existing region/refresh behavior |
| `LIFE_TZ` / `--tz` | CLI and server | CLI sends its effective timezone; server clock remains authoritative |

Only the server loads the root `.env`. For a non-default URL, explicitly configure `LIFE_API_TOKEN` in the client's environment. The reusable client requires HTTPS for non-loopback URLs and refuses redirects so it cannot forward a bearer token to another host. Nothing is deployed by these commands.

## HTTP contract

`GET /openapi.json` is an authenticated OpenAPI 3.1 document generated by `@hono/zod-openapi`. It lists every operation. Shared domain input schemas come from the existing Zod contracts; validation inside the business layer returns the existing rejection receipts.

Each operation is `POST /v1/<operation>` with JSON `{ "args": [...], "timezone"?: "<IANA zone>", "medium"?: "movie|show|game|book" }`. Arguments follow the corresponding method signature in [the tools brief](README.md). `medium` scopes only `title.*` operations, including `title.catalog.*`. Omit optional trailing arguments; use `null` for an omitted optional positional slot. A `null` inside an input object still clears that field.

For example, after exporting `LIFE_API_TOKEN` in your shell:

```sh
curl http://127.0.0.1:4319/v1/task.add \
  -H "Authorization: Bearer $LIFE_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"args":[{"title":"Example task"},{"actor":"neel","key":"example-task-1"}]}'

curl http://127.0.0.1:4319/v1/task.list \
  -H "Authorization: Bearer $LIFE_API_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"args":[]}'
```

A completed invocation returns `{ "ok": true, "result": <domain result> }`. **For writes, inspect `result.ok` and `result.outcome`**: an invocation can successfully return a rejected receipt, duplicates, or a required decision. Warnings and partial outcomes are retained. Null getters mean no matching record, just as in the core library.

A transport or thrown operation error returns `{ "ok": false, "error": { "code", "message", "issues"? } }`. HTTP status is 400 for invalid/rejected requests, 401 for authentication failure, 404 for unknown routes/sessions, 413 for requests over 10 MB, 500 for internal failures, and 503 for unavailable dependencies. Domain not-found errors may be returned as a rejection with a descriptive message; the CLI preserves its `not_found` classification.

The CLI retains exit codes 0/1/2/3/64. `api_unavailable` joins dependency failures at exit 3; `unauthorized` exits 1. No write is retried automatically. A lost response can follow a committed write: read back the state, or retry using the same `ctx.key`. Concurrency-sensitive writes use `ctx.ifVersion`. Keep keys stable across interfaces when retrying the same logical action.

Public namespaces are `catalog`, `task`, `project`, `section`, `label`, `filter`, `account`, `calendar`, `event`, `views`, `title`, `title.catalog`, and `media`. Every public asynchronous operation on these interfaces is exposed. `title.scoped(medium)` becomes the `medium` request field. Infrastructure objects (`store`, credentials, adapters, clock, close) are not callable HTTP operations.

Additional operations:

| Operation | Arguments | Result |
| --- | --- | --- |
| `catalog.resolve` | `[medium, text, { year?, externalId? }?]` | Complete read-only lookup using the existing confidence/detail/availability flow |
| `catalog.availability` | `[medium, externalId]` | Live availability outcome without writing a title |
| `export` | `[]` | Complete consistent export, including deleted records and log, never credentials |
| `display.indexes` | `[]` | Projects, calendars and accounts, including deleted records, for display/reference resolution |
| `system.info` | `[]` | API version, effective timezone, region |
| `system.doctor` | `[{ online?: boolean, actor?: string }?]` | Existing diagnostic report, executed on the server |
| `system.migrate` | `[]` | Applies migrations on the server's configured database; `{ migrated: true }` |
| `account.add` | `[{ provider: "google", label?: string, timeoutMs?: number }, ctx]` | Connection session |
| `account.connection` | `[sessionId]` | Current connection session |

Import data is JSON, never a server filesystem path. The CLI reads the input file locally and sends its contents; export downloads data before writing a local file. The manual Google and catalog smoke scripts also use the API; running them still requires explicit target arguments and can contact live providers.

Pagination, uploaded files larger than the body limit, and deferred media imports are not introduced by this milestone.

## TypeScript clients

Add `@life-os/tools` as a workspace dependency in a consuming app (for example, `"@life-os/tools": "workspace:*"`). The browser-compatible client has no runtime dependency on database, filesystem, or provider code:

```ts
import { createClient } from "@life-os/tools/client";

const life = createClient({
  url: "https://your-life-api.example",
  token: "your-configured-token",
  timezone: "America/Los_Angeles",
});

const tasks = await life.task.list();
const books = await life.title.scoped("book").list();
const receipt = await life.task.complete(taskId, {
  actor: "neel",
  key: "stable-completion-id",
});
```

Server-rendered web code should keep the token server-side. A direct browser client requires an explicitly allowed origin and secure token handling; an iOS client can send the same JSON using its standard HTTP stack. The server remains the only database/provider client.

## Google connection sessions

`account.add` starts sign-in and returns `{ id, status: "pending", url? }`. Poll `account.connection` until the URL appears, open it once, and continue polling. Completion returns `{ id, status: "complete", receipt }`; inspect the receipt, including first-sync warnings. Failure returns `{ id, status: "failed", error }`. Sessions expire after 15 minutes and do not survive a server restart. Check `account.list` before starting another session after an uncertain outcome. The TypeScript client and CLI perform this polling automatically.

By default Google redirects to the existing ephemeral desktop loopback listener; open the consent URL on the API host. For a browser on another device, configure a Google **web application** OAuth client with its authorized redirect URI, and set the server's `LIFE_GOOGLE_REDIRECT_URI` to the identical `https://<api-host>/oauth/google/callback`. The URI is fixed by server configuration and cannot be supplied by an API caller. That callback is public because Google redirects a browser without an API token; one-use expiring OAuth state and PKCE protect the exchange. Tokens and credentials stay on the server.

## Implementation and verification

- `src/api/app.ts`: Hono application and OpenAPI routes.
- `src/api/operations.ts`: explicit operation allowlist, compile-time checked against the core interfaces.
- `src/api/client.ts`: typed HTTP adapter used by `life` and reusable by web clients.
- `src/api/diagnostics.ts`: existing diagnostics moved off the CLI.
- `src/api/server.ts`: Node server, backend configuration, lifecycle.
- `src/api/oauth-callback.ts`: connection between Google's redirect and the existing OAuth implementation.

Run `bun run typecheck` and `bun run test` from the root. The API and CLI run directly on Node; no frontend build or snapshot validation step remains. Tests use disposable PostgreSQL schemas and fake provider/catalog adapters. CLI regression tests now run through real loopback HTTP servers; API-specific tests cover authentication, full route coverage, concurrency, idempotency, atomic batches, imports, null handling, scoped titles, timezones and transport failures. OAuth tests cover both desktop and API-hosted callbacks without contacting Google.
